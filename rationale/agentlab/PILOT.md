# Agent-improvement experiment: first bounded slice

The objective is faster **correct** application construction and conversion
without losing behavior or making the next change harder. The scripts and
corpus here make that question testable; the first run did **not** establish an
improvement. This is an intermediate pilot slice, not permission to make a
new rule mandatory.

## What ran

- Twelve authored, distinct JSON-lines scenario families carry 81 base probes,
  24 independent followups with 60 probes, and 420 input/output pairs.
  `CORPUS.md` audits requirement-changing base-output overrides. Contract
  loader and producer tests reject malformed fixtures and known state faults.
- A reproducible CLI produced two implementation-policy variants of inventory
  and funds. Both variants passed their independent base contracts. Different
  seed parity changes only an equivalent range expression, not the workload.
- Fresh agents produced ordinary raw applications for all twelve families
  from requirements without probe answers. All twelve subsequently passed the
  base oracle on a separate machine. One of the two five-family generator tasks
  lost its model connection after writing its files; its artifacts were
  recovered and verified, but its interrupted batch is not a timed-success
  observation. Passing probes does not certify the other ten authored oracles
  against independent reference models. One recovered agent-authored self-test
  fails because it expects a four-item batch to succeed where the declared
  maximum is three; the artifact and that failure were retained rather than
  rewriting its test after the run. Its separate base-oracle check passed.
- Two fresh agents attempted to convert raw inventory/funds applications and
  two more built them from scratch using Tesser guidance under 15-minute task
  bounds. Independent base behavior checks passed for their copied artifacts,
  but **all four failed** the zero-findings Tesser architectural gate. They are
  unsuccessful current-toolkit attempts, regardless of pytest and mypy passes.
  A controller clarification allowed a module entrypoint instead of a root
  `application.py`, applied symmetrically and recorded as intervention.
- Four separately prepared fresh agents performed the predeclared policy
  comparison's one withheld change per family/arm. All four passed the full
  base-plus-followup oracle within a 180-second release-to-verification window.
  See `COMPARISON.md` for exact times and the **inconclusive** decision. These
  subjects were deliberately nonconformant; they are not converted controls.

## Reproduce the tooling

From the repository root with Python 3 installed:

```sh
go test ./rationale/agentlab ./internal/experiment/... ./internal/experimentcorpus/... ./cmd/tesser-experiment/... ./cmd/tesser-corpus/...
go run ./cmd/tesser-corpus --family reserving-inventory --variant structured --seed 1 --out /tmp/inventory-subject
go run ./cmd/tesser-experiment brief --scenario rationale/agentlab/scenarios/reserving-inventory.json
go run ./cmd/tesser-experiment verify --scenario rationale/agentlab/scenarios/reserving-inventory.json --candidate /tmp/inventory-subject --command-json '["python3","-B","application.py"]' --result /tmp/inventory-result.json --deadline 30s
```

The result file must be outside the candidate tree. `trial` additionally
accepts a **local agent executable** and measures task release through
independent verification under one deadline; `internal/experiment/TRIALS.md`
describes its inputs and evidence. It does not fabricate a provider, replay
the Capy-task runs above, or know subscription/machine usage. Workloads execute
only on disposable cloud machines, never on a personal computer.

## What remains before an improvement claim

No converted subject passed the architectural gate, so the agreed comparison
of fresh followup effort on original, baseline-converted, and
candidate-converted snapshots could not run. There is no measured speedup,
cost benefit, or Tesser-rule victory. Provider usage, machine costs, and active
human labor are unknown; the controller-observed times include transfer and
queue latency and cannot rank agent edit speed. The controlled producer covers
two of twelve families; the other ten raw applications were agent-authored,
not generated by a deterministic implementation producer. Runtime integration
with brokers, actors, streaming servers, game engines, and model providers was
not exercised by these protocol-level workloads. No reliable semantic naming
score was established.

The next bounded comparison requires checker-clean baseline and candidate
conversions first, frozen across original and followup runs; repeated matched
trials, independent oracles for additional families, and real resource
instrumentation are needed before promoting or retiring any Tesser rule.
